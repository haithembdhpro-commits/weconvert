# YouCan → WeConvert CRM (phase 1)

This connector receives **new** YouCan orders through signed `order.created` and `order.updated` REST Hooks. For every delivery, it loads the complete order from YouCan's Admin API, checks COD and DZD, then creates or updates the corresponding CRM order in the selected store. The platform's order, payment, confirmation and shipping statuses are source metadata. CRM confirmation, assignment, stock reservation and ZR shipment state are independent. It never imports the YouCan history on connection.

## Configure the YouCan application

1. In the [YouCan Partner Dashboard](https://partners.youcan.shop/), create an external application with **Embedded = False**. Register `https://loxdcfxxefigfchmrwzy.supabase.co/functions/v1/weconvert-youcan/callback` as its OAuth redirect. The CRM URL is `https://weconvert-cod-studio-ht26.citrus-mug-9991.chatgpt.site/#integrations`.
2. Allow `read-orders`, `view-store-info` and `edit-rest-hooks`. The connector installs `order.created`, `order.updated` and `app.uninstalled` subscriptions pointing to `https://loxdcfxxefigfchmrwzy.supabase.co/functions/v1/weconvert-youcan/webhook`. An already existing subscription to the same event and target is reused by YouCan.
3. Set `YOUCAN_CLIENT_ID` and `YOUCAN_CLIENT_SECRET` in **Supabase Edge Function secrets**, not in the browser, repository or CRM tables. Merchants can save a channel draft without these server credentials; authorization then clearly remains pending. OAuth access and refresh tokens are kept in Supabase Vault per CRM connection. YouCan may return an `expires_in` near 100 years; preserve this lifetime as a bigint rather than truncating it or refreshing a valid token after one year.
4. As an owner/admin, open Integrations → YouCan → Nouveau canal, enter its name and HTTPS store URL (`https://my-store.youcan.store` or its primary custom domain), then authorize. The optional extra COD gateway labels are under advanced options. A cryptographic state expires after 10 minutes and can be used once. The callback reads `/me` to bind YouCan's immutable store UUID to the CRM store and checks that the authorized store's domain or canonical slug matches the URL entered. A mismatch leaves the channel pending with an actionable error. One YouCan store cannot be active in two CRM businesses.
5. Place a **new** COD order in DZD after connection with a customer phone, wilaya, city, and products. Check that it reaches the confirmation queue with status “Nouvelle”, the source journal shows “Reçue”, and the connection changes to “Réception vérifiée”. If webhooks were not installed, use “Réactiver les webhooks”; the state remains awaiting a first signed delivery until the test passes.

`verify_jwt=false` on this Edge Function is intentional: YouCan cannot send a Supabase JWT. The webhook verifies HMAC-SHA256 over the **raw** request body with the app secret before using `store_id`; interactive connect/repair/disconnect calls verify the user's Supabase JWT and an owner/admin role in the database. The callback accepts only an outstanding OAuth state. Invalid or unsupported deliveries return 4xx; transient API or database failures return 5xx for YouCan's retries. Delivery ID, order hash and source `updated_at` handle repeats and delays; an agent-edited order or ambiguous same-time change is flagged for review without overwriting confirmation or reserving stock.

The customer address and payment details returned by `GET /orders/{id}?include=customer,variants,payment,shipping,discount,refunds` must be checked on real merchant stores. Missing or inconsistent required information is logged as skipped rather than invented. Tracking/attribution is **unverified** for YouCan orders in this phase; no `Purchase` or Meta proof is inferred from their arrival. Orders that predate the connection are skipped even if a later update triggers a webhook.

## Validation and rollout

The repository includes a pure normalizer test (`tests/youcan-domain.test.mjs`) and a self-rolling-back SQL fixture (`tests/youcan.sql`) covering two businesses, agent permissions, deduplication, long-lived tokens, old orders and CRM edits. On 27 October 2026, the WeConvert YouCan Partner app was configured with the three required scopes, OAuth completed for `weconvert.youcan.store`, the store domain was verified, and all three REST Hook subscription requests returned success. The connector remains `awaiting_webhook` until a new signed order delivery proves reception. Before enabling merchants broadly, verify raw signature, error retries, uninstall, and a live COD order from at least two separate YouCan stores. Tracking and attribution remain unverified.
