# Shopify → WeConvert CRM (phase 1)

WeConvert receives new COD orders in DZD through `orders/create` and `orders/updated`. The Shopify status is source metadata only. COD confirmation, stock reservation and ZR delivery remain CRM decisions. No historical order backfill is started by connecting a shop. One Shopify shop maps to one CRM store; each company, store, connection, delivery and external order ID is scoped separately.

## Shopify app setup before a merchant can connect

1. Create a Shopify Partner/Dev Dashboard app distributed for the intended SaaS audience. Configure it as a standalone app with the allowed redirect URL `https://loxdcfxxefigfchmrwzy.supabase.co/functions/v1/weconvert-shopify/callback`. Its application URL can point to `https://weconvert-cod-studio-ht26.citrus-mug-9991.chatgpt.site/#integrations`.
2. Request the `read_orders` scope and protected customer data required for names, phones and shipping addresses. Shopify can redact unapproved fields; a successful OAuth alone does not prove that order webhooks contain enough information to confirm a COD order.
3. Set the app-specific HTTPS subscriptions `orders/create`, `orders/updated` and `app/uninstalled` to `https://loxdcfxxefigfchmrwzy.supabase.co/functions/v1/weconvert-shopify/webhook` (API version `2026-10`). Install the configuration through the Shopify app release process. Shopify signs each raw payload with the app client secret.
4. In Supabase Edge Functions **secrets**, set `SHOPIFY_CLIENT_ID` and `SHOPIFY_CLIENT_SECRET` from that app. Do not put them in `src/config.json`, a browser bundle, a database row, a chat message or version control. The callback uses a 10-minute single-use state, validates Shopify's HMAC and stores expiring offline OAuth credentials in Supabase Vault. Refresh them before future authenticated Admin API calls; webhook ingestion itself does not need the access token.
5. Test from two merchant development stores. In each CRM store, enter the shop's permanent `*.myshopify.com` domain and any additional **exact** manual COD payment gateway names, then finish Shopify authorization. Place a COD test order in DZD with a phone, wilaya, address and products. Confirm the journal says « Reçue » and the connection changes from « webhook en attente » to « réception vérifiée ». A paid/fulfilled/cancelled Shopify status must leave the CRM confirmation status untouched. Validate a retry and delayed update.

**Distribution gate:** Before public app distribution, implement and test Shopify's mandatory privacy webhooks (`customers/data_request`, `customers/redact`, `shop/redact`) and the related data request/redaction workflow, including related CRM notes and shipment records. This phase deliberately does not declare those topics or claim App Store compliance. Do not activate merchant distribution until that work, protected customer data approval and a real merchant end-to-end test are complete.

**Shop binding (28/10/2026):** the webhook HMAC covers the body only; `X-Shopify-Shop-Domain` is not signed. At OAuth time the callback reads `shop.json` with the new token and stores the numeric shop id (`external_shop_id`). An order webhook is accepted only if its `order_status_url` path carries that id (`/<shop_id>/orders/…`); `app/uninstalled` must name the same `myshopify_domain` and id. A mismatch is journaled as `SHOP_MISMATCH` and acknowledged with 200 (no retry loop). Connections made before this change have no stored id: only an `order_status_url` on the shop's own `*.myshopify.com` host is accepted, so a store using a custom domain must reconnect once. **Disconnect** removes the tokens from Vault, then revokes the grant at Shopify (`DELETE /admin/api_permissions/current.json`, refreshing an expired token first); a failure is journaled as `REVOKE_FAILED` and the merchant should uninstall the app from Shopify admin.

**Operational notes:** Webhooks are at-least-once and can arrive out of order. WeConvert uses delivery ID, an order content digest and Shopify's `updated_at`; a same-time ambiguity or a CRM-edited order is flagged for review. A rejected order (non COD, wrong currency, missing phone/wilaya, refund, malformed amount) is logged without creating an untracked historical sale. Errors from the DB return 503 so Shopify can retry. Secret rotation, webhook recovery and new-scope reauthorization need operational procedures before broad rollout.
